feat: implement CI/CD pipeline with GitHub Actions

This commit implements Phase 1 of the CI/CD pipeline specification,
providing automated build verification, testing, and code quality
checks for the Home AI Index mobile application.

## Features Implemented

### GitHub Actions Infrastructure
- Main CI workflow with parallel lint and test execution
- Conditional release builds (main branch only)
- Automatic build number incrementation from git commits
- Coverage enforcement (80% minimum threshold)
- Smart artifact retention (7-day debug, 30-day release)

### Reusable Composite Actions
- setup-flutter: Flutter SDK setup with caching
- run-tests: Test execution with coverage validation
- build-mobile: Android builds (debug/release) with signing

### Helper Scripts (Bash)
- setup-android.sh: Keystore decoding and signing setup
- increment-build-number.sh: Automatic versioning
- verify-secrets.sh: Secret validation before builds
- upload-coverage.sh: Coverage reporting and PR comments

### Android Configuration
- Release signing configuration in build.gradle.kts
- ProGuard rules for Flutter, TensorFlow Lite, ML Kit
- Debug build suffix and version naming
- Graceful fallback when signing credentials unavailable

### Documentation
- Comprehensive CI/CD setup guide (300+ lines)
- Keystore generation and secret configuration
- Troubleshooting and best practices
- Updated README with CI badge and coverage badge

## Technical Details

**Triggers**: Push to main/develop/feature/**, PRs to main/develop
**Runners**: ubuntu-latest (Phase 1 constraint)
**Platforms**: Android only (iOS in Phase 2)
**Jobs**: 
  - lint (5 min timeout)
  - test (10 min timeout, 80% coverage required)
  - build-android (15 min timeout, depends on lint+test)

**Caching Strategy**:
  - Flutter SDK (~/.flutter)
  - Pub dependencies (~/.pub-cache)
  - Gradle dependencies (~/.gradle)
  - Expected cache hit rate: ~90%
